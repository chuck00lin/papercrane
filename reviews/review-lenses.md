# Review lenses

Project data for `skills/shadow-reviewer.md`. Owner: human. The shadow reviewer reads this
file at the start of every review and writes an answer to every question in it.

The rows below are illustrations to be replaced with the project's own. A review run against
the illustrations alone must say so in its header. Three parts: lenses (questions put to the
text in the pre-pass), the trap catalog (ways a reviewer at this venue misjudges a paper),
and calibration questions (put to the finished review). Three to five entries per part is
usual; add one when a real review, in-house or cold, found something these did not.

## 1. Lenses

Each lens: a name, the question it asks of the text, and what a failing answer looks like.

| Lens | Question | A failing answer looks like |
|------|----------|-----------------------------|
| Load-bearing anchor | Which fact id, if its value moved, would change the conclusion? | several sentences depend on one fact that no second run or reference measurement supports |
| Boundary stated | Under which conditions (site, period, operator, material, scale) do the authors say the result holds, and where do they say it? | the boundary appears only under Limitations while Results and Abstract read without one |
| Delta in one sentence | What does a reader know after this paper that the nearest prior work did not already tell them? | the delta needs a paragraph, or is a change of method with no change in what is known |

## 2. Trap catalog

Each entry: the trap, how it shows in a review, and the habit that guards against it.

| Trap | Shows as | Guard |
|------|----------|-------|
| Anchoring on the first flaw | the first problem found colours every later paragraph; later strengths are read as compensations | finish the pre-pass before marking anything |
| Unfamiliar read as wrong | a method outside the reviewer's own toolkit is flagged as a defect rather than examined | a different method is a NOTE unless it changes the conclusion |
| Counting instead of weighing | severity judged by the number of comments, so a text with many small issues outranks one with a single fatal gap | write the top-line finding before the list |

## 3. Calibration questions

Answered in writing at the end of the review file.

1. If the text were published unchanged, would a reader at this venue be misled about anything? A yes caps the verdict at major revision.
2. If only one finding could be kept, which one, and is it the first line of the file?
3. Is every BLOCKER backed by a quoted sentence and a named ground (shadow-reviewer 4.7), rather than by an impression?
